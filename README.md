# cave-story-assist

A browser-playable *Cave Story* (洞窟物語) built for **learning Japanese**. You play the game; the original Japanese dialogue is drawn inside the game's own text box, with furigana, and every word is clickable for its reading and meaning. The English translation sits in the sidebar (blurred until you hover, if you want to test yourself), and words you want to keep go into a study list you can export as CSV. Each word shows whether it is a common word and its JLPT level. A **rewind** slider (one minute) and a 5-second rewind button (Backspace) let you undo mistakes, and three **save states** let you save and restore the exact game at any moment.

Sister project to doom-assist, wolf3d-assist and zork-assist.

## What's here

- `engine/` — [EXL's NXEngine fork](https://github.com/EXL/NXEngine) (SDL 1.2 rewrite of Cave Story by Caitlin Shaw), compiled to WebAssembly with Emscripten. Changes on top of the fork:
  - `sdl1compat/` — a small SDL 1.2 → SDL2 layer (the engine needs colour-key blits and `.pbm` loading that Emscripten's built-in SDL1 shim doesn't do).
  - `tsc.cpp` reports each chunk of script text to the page (`Module.assistText`), so it can show the matching Japanese line.
  - `TextBox/TextBox.cpp` can skip drawing its own (English) characters so the page draws the Japanese instead; `assist.cpp` exports the entry points the page uses (text box layout, HP, god mode, heal).
  - Web-build fixes: yield to the browser in `SDL_Delay`, auto-run the data extraction, no TTF font, saves under `/saves` (IndexedDB).
- `web/index.html` — the page: game canvas, Japanese overlay, word panel, history, study list.
- `web/snapshots.js` — rewind buffer and save states. The engine calls the page once per game tick (`assist_frame_hook`), when nothing is suspended in an ASYNCIFY sleep, so all game state is in WebAssembly memory. Rewind keeps one snapshot per second for a minute as page-level diffs (the screen surface is skipped); save states are a full gzip-compressed memory image in IndexedDB, tagged with the build id (a state from another build is refused).
- `web/script-data.json` — Japanese stage names plus every script event in the game with the English text, the original Japanese tokenized with furigana, and dictionary glosses. Generated by `tools/build-script-data.mjs`, committed.
- `data/en/` — the freeware Windows release with the Aeon Genesis English translation (v1.0.0.6). NXEngine extracts the sprites, sounds and stage tables from `Doukutsu.exe` on first boot.
- `data/jp-tsc/` — the script (`.tsc`) files from Studio Pixel's original Japanese freeware release (`dou_1006.zip`), used only to build `script-data.json`.

## How the Japanese gets matched

The Japanese and English releases share the same event numbers, so a line is identified by *(stage file, event number, text)*. The engine reports the English text it is showing; the page finds that line in `script-data.json` and shows the Japanese at the same position in the event. For the ~8% of events where the translation split the text differently, the whole Japanese scene is shown instead and flagged as approximate. While the Japanese display is on, the engine draws no English of its own for dialogue, item text or the stage-name banner. Engine-drawn UI that isn't in the scripts (title menu, pause/options screens, credits, save-slot names) is still English.

## Running locally

```bash
# 1. Get the Emscripten SDK (one-time; ~1GB, not checked into the repo)
git clone https://github.com/emscripten-core/emsdk.git tools/emsdk
cd tools/emsdk && python emsdk.py install 6.0.6 && python emsdk.py activate 6.0.6 && cd ../..

# 2. Activate it in your shell
source tools/emsdk/emsdk_env.sh

# 3. Build the engine (writes web/nx.js, nx.wasm, nx.data)
bash engine/build-emscripten.sh

# 4. Serve it (browsers block wasm/fetch from file:// URLs)
cd web && python -m http.server 8090
# open http://localhost:8090/
```

### Regenerating the Japanese data (optional; the result is committed)

```bash
cd tools && npm install
mkdir -p cache/jm
# download JMdict (jmdict-simplified, English) and unpack the .json into tools/cache/jm/
#   https://github.com/scriptin/jmdict-simplified/releases
# download the JLPT vocabulary list to tools/cache/jlpt.json
#   https://raw.githubusercontent.com/Bluskyo/JLPT_Vocabulary/main/data/vocab/results/JLPT_vocab_ALL.json
# (stage names come from data/jp-tsc/stage-names.json, made by tools/extract-jp-stage-names.mjs)
node build-script-data.mjs ../data/jp-tsc ../data/en/data ../web/script-data.json
```

## Deployment

Pushing to `main` runs `.github/workflows/pages.yml`, which builds the engine in CI and publishes `web/` to GitHub Pages (repo Settings → Pages → Source: GitHub Actions).

## In-game debug console

Press <kbd>`</kbd> (backtick) while playing, type a command and press Enter; <kbd>Tab</kbd> completes. Backspace deletes text while the console is open (otherwise it is the 5-second rewind). Arguments in `[]` are optional.

| Command | What it does |
| --- | --- |
| `god [0/1]` | God mode on/off |
| `hp N`, `maxhp N` | Set current / maximum HP |
| `giveweapon N`, `dropweapon [N]` | Give / remove a weapon: 1 Snake, 2 Polar Star, 3 Fireball, 4 Machine Gun, 5 Missile Launcher, 7 Bubbler, 9 Blade, 10 Super Missile, 12 Nemesis, 13 Spur |
| `level 1-3`, `xp N`, `ammo N`, `maxammo N` | Current weapon's level, experience and ammo |
| `warp N` / `warp <stage name>` | Go to a stage by number or by the start of its (English) name |
| `script N` | Run script event N from the current stage |
| `flag N`, `clearflags` | Toggle story flag N / clear all flags |
| `giveitem N`, `takeitem N` | Add / remove inventory item N |
| `equip <name> [0/1]` | Equip: `booster08`, `booster20`, `map`, `armsbarrier`, `turbocharge`, `airtank`, `mimigamask`, `whimstar`, `nikumaru` |
| `spawn [count] <object name>` | Spawn an object or enemy; `animate N` sets its state |
| `killall` | Kill every shootable object on screen |
| `infinitedamage [0/1]` | Your shots do huge damage |
| `movemode 0/1/2` | 0 normal, 1 zero-gravity, 2 free-fly (also <kbd>V</kbd> toggles fly in debug) |
| `boa N` | Set the stage boss's state |
| `sound N`, `music <name or N>` | Play a sound effect / song |
| `qua [x]` | Screen shake |
| `cre` | Jump to the good-ending credits |
| `reset` | Reset the game |
| `fps [0/1]` | Show frames per second |
| `player->hide 0/1`, `player->inputs_locked 0/1`, `game.frozen 0/1`, `textbox.SetVisible 0/1` | Low-level toggles |

Settings commands (`instant-quit`, `no-quake-in-hell`, `inhibit-fullscreen`, `emulate-bugs`, `displayformat`, `skip-intro`) are saved in the engine's own settings file, which this web build doesn't persist.
